# 0014 — Presentation Studio in Phase 7: database version 3, the kind registry, presentation content schema 1, the package boundary and hosts

**Status:** Accepted in Phase 7. Round 1 laid the foundation (decisions 1 to 9). Round 2 (EDITOR, DESIGN, CONTENT, SHOW, EXPORT) builds on it at the `// @phase7:<area>` markers (decision 10) and extends this record in place (decisions 11 to 15); Round 3 and the final fixes of 2026-11-15 are decision 16.

## Context

Phase 7 adds a third kind of item, the presentation (brief: slides, layouts, themes, masters, text, images, tables, charts, shapes, diagrams, backgrounds, alignment guides, notes, presenter mode, transitions, animations, PPTX and PDF export). Until now the database (version 2, [ADR 0006](0006-migrations-and-safety-copies.md)) had stores for two kinds, and five code paths listed those stores by name: attachment clean-up, backup export, backup import, the pre-upgrade backup (`readBackupAt`) and the safety-copy export (audit `backups/phase7-audit-20261114.md`, storage-compat, "The current build hard-codes store lists outside STORES").

Older builds matter as much as this one. The audit found (storage-compat, app-shell):

- Phase 3 to Phase 6 builds clean up attachments by reading only the document and diagram stores and drafts, once a day and after every Empty trash. An older build that could open a database holding presentations would delete pictures only presentations use.
- Their list pages index `MODULES[item.kind]` without a guard, so a `presentation` row in `item_index` would crash Dashboard, Files, Recent, Favorites and Trash; their Empty trash throws on the unknown kind.
- IndexedDB creates object stores only during a version change.

## Decision

1. **One database, version 3 (owner's decision, 2026-11-14).** `SCHEMA_VERSION` is 3. `MIGRATIONS[2]`, appended, creates `presentations` (keyPath `id`) and `presentation_versions` (keyPath `id`, index `by_item` on `itemId`), shaped exactly like the document stores, and nothing else: no existing store, index or record is read, changed or removed, and `item_index`, `drafts` and `attachments` are already shared by every kind, so there is no backfill. It runs, like every upgrade, only after the verified pre-upgrade safety copy (`<db>-backup-v2` for a Phase 6 profile, `-backup-v1` for v0.1.0) or a backup file made on the recovery screen ([ADR 0006](0006-migrations-and-safety-copies.md)); `MIGRATIONS[0]` and `[1]` are unchanged.

   **Consequence, accepted by the owner:** every build before Phase 7 (v0.1.0, Release 0.2, Phases 2 to 6) opens the database at its own version and IndexedDB refuses with `VersionError`. Those builds fail closed: every storage call rejects before touching anything, so they can neither clean up, purge, import into, overwrite nor delete the upgraded database (no build ever deletes the main database). They are not usable on that profile any more; ADR 0006 already accepted the same for v0.1.0 against version 2. Their Dashboard shows an empty home screen and their lists show "could not be read" (they cannot be changed). From this build on, a database made by a newer version shows a screen saying so (`UpgradeGate`, `NewerDataScreen`; the adapter's `failed` status carries `newerData: true` for `VersionError`). That screen replaces the whole app, including the "Update now" banner, and a plain reload keeps serving this build while a newer service worker waits, so when one is waiting the screen offers Update now (it activates the waiting worker, as the banner does); otherwise it offers Reload and says to close every Classroom OS tab and window if the screen comes back, and the Dashboard shows a read error instead of "Nothing here yet".

   Rejected: reusing the version-2 stores (older builds crash on presentation rows and their clean-up deletes presentation pictures), and a second database (no atomic Empty trash, clean-up or backup across kinds; two upgrade paths; contradicts [ADR 0001](0001-local-first-storage.md)).

2. **The kind registry.** `ItemKind` is `'document' | 'diagram' | 'presentation'`; `ITEM_KINDS` appends `presentation` (order is never changed). `STORES` in `packages/local-storage/src/indexeddb.ts` maps each kind to its item and version store and is exhaustive (a kind without stores does not compile). Every store list is derived from it: `ITEM_STORE_NAMES` and `VERSION_STORE_NAMES` for backup export and import, `readItemStores(db)` (the registry's stores that a database or safety copy has) for the pre-upgrade backup and the safety-copy export, and attachment clean-up searches every object store except `attachments` (`referenceStores(db.objectStoreNames)`; searching more stores only keeps more). `packages/local-storage/src/kinds.test.ts` runs every per-kind operation for every kind (create, list, save and conflict, versions and restore, trash, duplicate, purge with drafts, version-image compaction, backup round trip, and clean-up keeping a picture referenced only by that kind's item, trashed item, version or draft). With the old clean-up list, the presentation cases fail.

3. **Backups stay format 2.** Presentations go in the existing `items` and `versions` arrays with kind `presentation`, and their pictures in the shared `attachments` array; `MAX_CONTENT_SCHEMA_BY_KIND.presentation` is 1. What older builds do with such a file (from the audit; their code cannot change): v0.1.0 refuses the whole file ("malformed item record"); Release 0.2 to Phase 6 import documents and diagrams within their own limits, skip presentation items and versions and count them ("… items need a newer version of the app and were left out"), and import presentation-only attachments, which their clean-up later removes (the file still has them). A separate top-level section was rejected because older builds would drop it without a word. The file's `schemaVersion` stays the highest content schema in it ([ADR 0007](0007-backup-format.md)); presentation schema 1 never raises it.

4. **Presentation content schema 1** (`packages/presentation-studio/src/types.ts`, the whole model for every group): `{ schemaVersion: 1, size: 960×540 (16:9) | 960×720 (4:3), themeId, theme, masters[], layouts[], slides[] }`. Units are CSS pixels at 96 per inch (960 × 540 is the 10 × 5.625 in PowerPoint/PptxGenJS 16:9 layout) and points for font sizes. A theme has the eleven OOXML colour slots (`light1` is the background and `dark1` the text, as with the default colour map) and heading and body fonts; colours are `#rrggbb` or `{ theme: slot }`. Masters and layouts hold placeholders (`title subtitle body picture chart table footer date slideNumber`, each with a box, a prompt and a text style) and decorations (elements). A slide has `id, layoutId, background?, elements[], notes, transition?, hidden?`. Elements are `text | image | shape | table | chart | diagram`, each with `id x y w h rotation locked? name? animation? placeholderId?`; shapes use 23 presets named as PPTX preset geometries; charts are `bar | column | line | pie | doughnut` with categories and series; a diagram element carries exactly the document `diagram` node's attributes (`source previewId naturalWidth naturalHeight title alt svgPreviewId`, `diagramNodeAttrs`), so the Phase 6 export helpers apply. Transitions are `none fade push wipe cover split zoom` (duration, direction or orientation) and animations entrance effects `appear fade fly-in zoom wipe` (order, trigger `on-click | with-previous | after-previous`, duration, delay, direction): what both PPTX and the slide show can play. Rich text in text boxes, shapes, cells and notes is Tiptap JSON limited to a small vocabulary (paragraph with alignment, bullet and ordered lists, hard break; bold, italic, underline, strike, sub/superscript, link, highlight, text colour/font/size). **Attachment ids are always their own string values** (`attachmentId`, `previewId`, `svgPreviewId`), never inside a larger string, so clean-up sees them (`collectReferences`).

5. **The schema rule.** `PRESENTATION_V1_VOCABULARY` (`compat.ts`) lists every field and closed value set of schema 1, written out rather than imported from the types, and is frozen once Phase 7 is released (until then a Round 2 group may append what its part of the model needs and records it here). `presentationNovelty` names the first thing outside it. `PRESENTATION_SCHEMA` is 1, `migratePresentation` refuses newer content and works on a copy, a missing stored `schemaVersion` reads as 1, and a stored one that is not a whole number of at least 1 (for example `"2"` or `2.5`) is refused as unreadable, so that content opens in protected view and its stored value is never overwritten, and `presentationSchemaFor` returns 1 for everything this build can represent. A later phase adds schema 2 for content outside the vocabulary, as documents and diagrams do ([ADR 0011](0011-document-format-phase4.md), [ADR 0012](0012-diagram-format-phase5.md), [ADR 0013](0013-document-diagram-integration.md)).

6. **Protected view.** `preparePresentation(raw)` gives `editable` only for well-formed schema-1 content inside the vocabulary (`presentationProblems`: types, ids, references between slides, layouts and masters, every element). Content from a newer version (`reason: 'newer'`) or damaged or unknown content (`'invalid'`) opens read-only from `displaySafe(raw)`, a deep copy that keeps what is readable and falls back to the built-in theme, master and layouts. The editor then never calls `onChange`, shows "Opened read-only to protect this presentation" with the reason, and offers "Download original data" (the stored content, unchanged).

7. **Package boundary and hosts.** `@dcos/presentation-studio` (a workspace package with `exports` `.` and `./templates`, `sideEffects: false`) imports only `@dcos/ui`, like the other studios: `tests/integration/boundaries.test.ts` lists it, and now also fails if any package with source code is missing from its list (before, a new package went unchecked). The boundary is not widened. App features come through hosts declared in `src/hosts.ts`: `PresentationDiagramHost`, structurally identical to document-studio's `DiagramHost` (checked both ways at compile time by `tests/integration/presentation-hosts.test.ts`), so the app can pass the host it already builds; `PresentationImageHost` (`putAttachment`, `loadAttachment`), implemented in `apps/web/src/lib/presentationHosts.ts` on the attachments store and passed by `EditorPage` to presentations only. Toasts use `@dcos/ui`'s `useToast`. Shared UI that later groups need from document-studio (Popover, ColorPanel…) moves its pure part into `@dcos/ui` with document-studio re-exporting it unchanged; nothing moved in Round 1.

8. **App shell.** `MODULES.presentation` (route `presentations`, frozen from now on; label Presentation, plural Presentations, icon Presentation, templates from `@dcos/presentation-studio/templates`, editor loaded lazily). Every place that listed two kinds now follows the registry: open-item tabs (`ITEM_KINDS`), the Dashboard (counts and the "Stored on this device" sentence over `MODULE_LIST`, a New button per module, a "Blank presentation" quick start; a quick start entry whose template is missing is left out), and the copy in Settings, Unsaved drafts, the upgrade recovery screen, the item lists, the web manifest and the page description. The New dialog has no import card for presentations, and the presentations list no import button, because there is no presentation import.

9. **Round 1 editor: read-only, no dead controls.** `PresentationEditor` shows the slide list (a listbox: click, ↑/↓, Home/End), the selected slide fitted to the window, and its speaker notes, all rendered from the model by `SlideView` (background from slide, layout or master; master and layout decorations; every element type; pictures and diagram previews through the image host, with a calm frame naming a picture that is not on this device). Placeholder prompts are never drawn by `SlideView` (they belong to the editor). Links inside a slide are drawn as link-coloured text, because a drawn slide is a picture (`role="img"`, or hidden inside a slide-list button) and must hold nothing focusable; the speaker notes keep live links (`RichText links`). Charts are shown as a labelled frame until the CONTENT group's SVG renderer. Nothing editable is shown, and the editor never calls `onChange`, so opening a presentation does not change it.

10. **Round 2 hooks in at markers.** `// @phase7:EDITOR` (the editing stage, slide panel operations, autofit, editor shortcuts), `// @phase7:DESIGN` (templates in `create.ts`, `templates.ts` and the Dashboard quick start; themes, sizes, backgrounds, master view), `// @phase7:CONTENT` (the chart renderer, diagrams through the diagram host, `EditorProps.imageHost`/`diagramHost` for presentations), `// @phase7:SHOW` (slide show, presenter view, fullscreen toasts, show shortcuts) and `// @phase7:EXPORT` (`buildPptx` and `buildPdf`, run by `exportPresentation` in `export/index.ts`; the export menu). **Export plan:** PPTX with PptxGenJS 4.0.1 (MIT, the one approved new dependency, loaded only when exporting), with masters and layouts as slide masters, native tables and charts, preset shapes, pictures passed as `data:` URLs only (no network), diagrams as PNG with the Phase 6 `dcos-diagram` data, notes and hidden slides, and an fflate post-process adding `p:transition` and `p:timing`; PDF one vector page per slide through the slide SVG, svg2pdf and jsPDF (already used by Diagram Studio). Export notes say what each format loses and never claim that a PPTX can be imported back.

11. **Round 2a: the editor core (EDITOR, `packages/presentation-studio/src/editor/**` and `ui/**`).** Editable content opens in the editor; protected content keeps the read-only view of decision 9.
    - **Slide text uses its own Tiptap extension set** (`editor/textExtensions.ts`: StarterKit without headings, quotes, code or rules; TextStyleKit without background colour and line height; Highlight, TextAlign on paragraphs, Subscript, Superscript, and Placeholder for prompts), never `documentExtensions()`, so a document change cannot change slide text. The package now lists these `@tiptap/*` packages as its own dependencies, at the versions the lock file already has (no new package; `boundaries.test.ts` is unchanged because they are not `@dcos` packages).
    - **What Tiptap returns is cleaned to the frozen vocabulary before it is stored** (`cleanRichText`: link `href` only, no `target`/`rel`/`class`, no list `type`, no null or default attributes, no empty text). Without this, the first save of any link would make the presentation open read-only (a test proves it). Schema 1 and `PRESENTATION_V1_VOCABULARY` are unchanged by Round 2a.
    - **One Tiptap editor** is mounted on the text box being edited and one on the current slide's notes; every other box is drawn by `RichText`. Ctrl/⌘+Z typed inside an editor undoes its own typing; everything else, including the Undo button while a box is edited (which ends the edit), is one editor-wide history of content snapshots (`editor/useEditorModel.ts`), where one text-editing session, one drag and one run of nudges are one step each. Selecting something else ends a run, and a session whose typing was all undone inside the box leaves no step.
    - **Copy and paste of slide objects** uses the web format `application/x-dcos-slide-elements` (JSON `{ format: 'dcos-slide-elements', version: 1, elements, tab?, seq? }`) on the system clipboard plus an in-app clipboard for the Paste button and browsers that send no clipboard event. Copy and Cut from the object menu and the ribbon reach the system clipboard too (a copy command run inside the click), and a pasted copy that is older than this tab's last copy gives way to it. Pasted objects are checked with `elementProblem` and the vocabulary and refused if this build cannot represent them, so a paste never makes a presentation open read-only. Copies get new ids and lose their placeholder link.
    - **Smart guides** (`editor/guides.ts`, pure): snapping within 6 screen pixels to the slide's edges and centre, other objects' edges and centres, and equal spacing in a row or column; Alt turns it off. Autofit 'shrink' scales text in `SlideView` (so thumbnails and later the show and exports agree), 'resize' keeps the box as tall as its text: while it is edited (`TextBoxEditor`) and after any other change to it (font size, autofit choice, width, theme) through a measurement in `Canvas` that becomes part of that change's undo step. Opening a slide never changes it.

12. **Round 2b DESIGN: themes, slide size, backgrounds, layouts, master view and templates (`packages/presentation-studio/src/design/**`).** Schema 1 and `PRESENTATION_V1_VOCABULARY` are unchanged: everything is stored in fields decision 4 already has.
    - **Themes.** The Design tab's gallery applies a built-in theme (colours and fonts); a colour set or heading/body font on its own gives `themeId: 'custom'` (name "Custom") unless the result equals a built-in theme. Everything that refers to theme slots and the heading/body fonts follows; explicit colours and fonts do not.
    - **Slide size** (16:9 ↔ 4:3; the width stays 960): text boxes and placeholders keep their font size and scale their top and height; shapes and pictures along the top or bottom edge stay on that edge and full-height ones span the new height; other objects keep their size and their centre's share of the height, shrinking (tables with their rows and columns) only when they would not fit.
    - **Backgrounds** (solid, two-stop gradient, picture stored through `PresentationImageHost` as its own `attachmentId`) apply to the selected slides; "Reset" removes the slide's own background; "Apply to all slides" sets the masters' background and removes the layouts' and slides' own, so new slides get it too. Master view sets the master's background or a layout's own (or back to the master's).
    - **Placeholders follow unless changed.** A slide object that fills a placeholder keeps its own copy of the box and text style. When a master or layout placeholder changes, each field (x, y, w, h, and each text-style field) of a layout placeholder or slide object that still equals the old value takes the new one; fields changed by hand keep the user's value. Decorations and backgrounds are not copied (slides draw their layout's and master's), so they follow at once.
    - **Change layout** (Design tab, slide menu "Layout…") moves placeholder objects to the new layout's placeholder of the same id, else the same kind, else title ↔ title and subtitle/body ↔ body, following the rule above; text with no place stays on the slide as an ordinary text box (only empty placeholders are dropped); missing text placeholders are added empty. "Reset slide" puts placeholder objects back to their layout's box and style and adds missing ones, keeping the text.
    - **Master view** replaces the ribbon and slides while open: the master and its layouts in a list, the chosen one on the editor's canvas (placeholders as prompt boxes that can be moved, resized, nudged and formatted, not rotated or typed into; decorations — text, rectangle, line, picture — added, edited, arranged, locked, copied and deleted). Layouts can get text placeholders (new slides and reset slides get them), have placeholders removed (slides keep what was typed in them) and hide the master's decorations. Everything is one step in the editor's single history.
    - **Templates**: Blank, Lecture (quick start "Lecture slides"), Project presentation, Lab results and Class report, in `design/templates.ts`, used by `createPresentation` and the New dialog; each has its own theme and only schema-1 content (a test opens each one editable, at both sizes). The "Blank presentation" quick start stays. Unknown template ids, including `Object.prototype` names such as `toString`, are refused.
13. **Round 2b SHOW: slide show, transitions, animations and presenter view (`packages/presentation-studio/src/show/**`).** Schema 1 and the vocabulary are unchanged: transitions and animations use the fields of decision 4.
    - **The show** is a modal `<dialog>` over the editor (so the app's toasts are drawn inside it, and the editor under it is inert). The page (`document.documentElement`, since a dialog cannot be made full screen itself) goes full screen from the click or key that starts it, and the dialog is then opened again so it stays above the full-screen page in the top layer (without that, WebKit drew the editor over the show); where that is refused or missing (iPhone Safari, some webviews) the show fills the window and says "Press F" or that full screen is not available. Leaving full screen with the browser's own Escape ends the show; the F key and the controls' button toggle it without ending. It starts from the beginning (F5, the ribbon's "Slide show" button), from the current slide (Shift+F5) or from a slide (slide menu "Play from this slide"). Keys: → ↓ Space Page Down N Enter next; ← ↑ Page Up Backspace P previous; Home/End; a number then Enter jumps (a hidden slide too); B/. and W/, blank the screen (the next press brings it back); Escape ends. A mouse click goes on; on touch screens a tap on the left third goes back, elsewhere on, and a horizontal swipe of 50 px moves. Keys pressed in the show never reach the editor (no undo, save or F5 reload under it). Hidden slides are skipped; after the last slide a black screen says "End of slide show. Click to exit."; the editor then shows the slide the show ended on, and the focus returns to what started it.
    - **Order** (`show/sequence.ts`, pure): "on click" starts a build step; "with previous" starts with the animation before it; "after previous" when it has finished; delays count from that moment. When a slide's first animation is not "on click", its first step plays by itself as the slide comes in. Back takes back the last step (never the automatic one), then shows the slide before fully built. `buildSteps` is exported so exports can group `p:timing` the same way.
    - **Playback** uses the Web Animations API (no library): two stacked layers for transitions (`fade` opacity; `push` both slides; `cover` the new one; `wipe` and `split` a `clip-path`; `zoom` scale), and the objects of a step animate with their delay and `fill: backwards`, so they stay in their first keyframe until their turn. Not-yet-built objects are hidden by their `data-element` id (every element view carries it; a test checks every element type). Direction words follow types.ts: a transition's direction is the way the new slide moves (push "From right" = `left`, PPTX `dir="l"`), an animation's is where the object comes from. **`prefers-reduced-motion: reduce` turns every transition and animation into a cut** (the tabs say so).
    - **Tabs.** Transitions: the effect for the selected slides, direction or orientation, a speed limited to the three PPTX can store (0.5, 0.75, 1 s; another stored duration is shown as it is), "Apply to all", and a preview drawn over the canvas (from the slide before, or from black). Animations: the entrance effect of the selected objects (None removes it), direction, start (on click / with previous / after previous), duration and delay in seconds (typing is one undo step), "Earlier"/"Later" in the slide's sequence, and a preview of every step in turn. Slide Show: From beginning, From current slide, Presenter view, Hide slide. Every change is one step in the editor's single undo history.
    - **Presenter view.** With a second window: the editor makes a `ShowLink` on a `BroadcastChannel` named `dcos-present:<session>` *before* it calls `window.open` (from the click, without `noopener`, so a blocked popup is seen as `null`) on the app route `#/presentations/presenter/:session` (outside the app shell, no editing session; `apps/web/src/pages/PresenterPage.tsx`). The presenter window says hello until the show answers with the presentation as it is in the editor (unsaved edits included) and where the show is; after that every move is sent both ways (state from the show, commands from the presenter), a reloaded presenter window is welcomed again, its closing is reported, and ending the show from either side ends both (the presenter window closes itself). The second window is used only after this handshake works: if `window.open` returns null, or no hello arrives within 4 s (Tauri or Android webviews, where a second window is not known to work), the second window is closed and the show *asks* — "Presenter view on this screen" or "Keep the audience view" — and never switches by itself, because the audience may be watching that screen (a mirrored projector would show them the notes; Round 3, decision 16). On touch-only small screens (`(hover: none) and (pointer: coarse)` below 768 px) the button opens that in-page presenter view directly. The presenter view has the current slide (as the audience sees it), the next slide (or "the next click plays an animation"), the notes, the slide number, a timer with pause, resume and reset, the time of day, and Previous, Next, Black screen and End show; the presenter window takes the show's keys too. The screen stays awake during the show where the Screen Wake Lock API exists.

14. **Round 2b CONTENT: pictures, shapes, tables, charts, diagrams, the inspector and placeholders (`packages/presentation-studio/src/elements/**`, the app's diagram host).** Schema 1 and the vocabulary are unchanged: everything uses the fields of decision 4.
    - **Pictures** come from the Insert tab, Replace, an empty picture placeholder, paste (files in the clipboard) and drag and drop. A file is refused when it is not a picture or is over 15 MB, made smaller when its longest side is over 2400 px, and stored as PNG when it is not PNG, JPEG or GIF (so PowerPoint and Keynote show every picture); it goes through `PresentationImageHost.putAttachment` and the element keeps only its `attachmentId`. The inspector sets fit (fit inside, fill and crop, stretch), crop per side (at least 5% stays visible), "Match the picture's proportions", Replace and alt text (empty alt text means decorative, and the inspector says so). Without an image host the picture controls are not shown.
    - **Shapes**: the 23 presets in a gallery; double-click, Enter, "Edit text" or a second tap edits the text inside with the same text editor as text boxes, and while it is edited the ribbon's text formatting applies to it. The inspector sets the preset (not to or from a line), fill (none or a theme/standard colour, opacity), line (colour, width, dash; arrowheads for lines) and flips. 'shrink' autofit scales shape text like text boxes; 'resize' grows the shape while its text is typed and otherwise never hides text.
    - **Tables** are inserted with a size grid or typed rows and columns (up to 30 × 12). Double-click (or Enter, "Edit cells") edits the cell under the pointer; Tab and Shift+Tab move, Tab in the last cell adds a row, Shift+click selects a range, Escape ends. Rows are kept as tall as their text (measured after each change and made part of it, as for 'resize' text boxes), a table resized with the handles scales its columns and rows to the new box, and the stored box always equals the sum of its columns and rows. The inspector: header row, banded rows, first column, text size, header fill, rows and columns above/below/left/right (or at the ends when no cell is active), delete row or column, cell fill and all/outside/inside/no borders for the selected cells (or all), and the table border. Tables with merged cells (which this build cannot make) are drawn and kept, but rows and columns cannot be added or removed in them.
    - **Charts** are drawn by a hand-written renderer (`elements/chart.ts`: column, bar, line, pie, doughnut; stacked bars and columns; title; legend top/bottom/left/right; value labels; "nice" axes that include zero; theme accents unless a series or slice has its own colour) as plain primitives that `ChartSvg` draws on the canvas, in thumbnails and in the show, and `chartSvgMarkup` writes as standalone SVG (rect, line, path, circle and text only) for the PDF export. The data grid ("Edit data…", double-click) edits categories, series names and colours (slice colours for pie and doughnut) and values; a value that is not a number is refused with a message; Save is one undo step and Cancel changes nothing.
    - **Diagrams** use the app's diagram editor through `PresentationDiagramHost` (new, from a Diagram Studio template, from my diagrams, from a diagrams.net file; double-click, Enter or "Edit diagram…" to edit). An edited diagram keeps its place and width; its height follows the new drawing. The settle protocol of document-studio is mirrored: the app is told whether the diagram got onto a slide (it did not when the presentation or the diagram went away meanwhile), and keeps the dialog's edits until then. **`useDiagramHost` takes an owner**: `{ docId }` keeps the Phase 6 document behaviour, words and storage calls exactly (DiagramDialogs.test.tsx is unchanged); `{ owner: { kind: 'presentation', id } }` files the dialog's drafts under the presentation (`drafts` store, kind `presentation`; localStorage key `dcos-diagram-dialog-draft:presentation:<id>:<session>`) as a plain record `{ format: 'dcos-diagram-dialog-draft', version: 1, note, base, source, title }`, not a document (only version-3 builds can open such a profile, decision 1), and the dialog speaks of slides. `EditorPage` passes the host to presentations and offers their kept edits ("Recover diagram edits"), which `applyRecoveredPresentationDiagram` puts over the diagram they were opened on, or onto the last slide. The presentation editor and Settings → Unsaved drafts never offer these drafts as presentation content, and attachment clean-up keeps the previews they refer to.
    - **The inspector** (beside the canvas on screens at least 1100 px wide since Round 3, below it and folded until opened on phones) shows the selected object's position, size and rotation (typed; Enter or leaving the field applies, Escape puts the value back) and its own settings; a locked object's settings are disabled. **Empty picture, chart and table placeholders** are drawn on the canvas only (never in thumbnails, the show or exports) with a button that fills them; the object takes the placeholder's box and `placeholderId`. The object menu gains "Replace picture…", "Edit chart data…", "Edit diagram…", "Edit cells" and "Edit text".

15. **Round 2b EXPORT: PowerPoint and PDF (`packages/presentation-studio/src/export/**`, the Export menu in the ribbon).** Schema 1 and the vocabulary are unchanged; exports only read content. The Export menu (PowerPoint (.pptx), PDF, PDF with speaker notes) loads `export/index.ts` on first use, so PptxGenJS 4.0.1 (MIT, pinned exact), jsPDF and svg2pdf are their own chunks; an item that cannot produce a file (no slides; every slide hidden, for PDF) is disabled. The toast says what was made and names every approximation (`ExportReport`); no note claims a PPTX can be opened again in Classroom OS.
    - **PPTX = PptxGenJS + post-processing.** PptxGenJS writes the package: each layout as a slide layout (title and body placeholders with their prompts — since Round 3 only text placeholders, see decision 16; PptxGenJS has one slide master, so the master's decorations are written onto each layout and the toast says so), pictures (always as `data`, never fetched; SVG and other formats are drawn to PNG first), native tables, native editable charts with their embedded workbooks, preset shapes, solid and picture backgrounds, notes and `show="0"` for hidden slides. `export/pptxPost.ts` then (fflate, entry order kept) replaces every text body with our own DrawingML (`export/drawingml.ts`: one `<a:pPr>` per paragraph, runs with bold/italic/underline/strike/baseline/colour/highlight/font, links with their relationships, bullets and numbering with levels, insets, anchor, autofit with the shrink scale worked out here), gives placeholder text its own position and object name back (PptxGenJS gives it the layout's), writes gradient fills and backgrounds, picture crops (`a:srcRect`, also for "fill and crop"), unique shape ids, object names, the theme's colour scheme in `theme1.xml`, missing chart values as gaps (no empty `c:v`, no empty workbook cell), and `p:transition` and `p:timing` after `p:clrMapOvr` (ECMA-376 order). Every edit looks for an exact pattern and throws when it is missing, so a library change cannot silently drop content. Transitions use the base PresentationML elements (fade, push, wipe, cover, split, zoom) with the three OOXML speeds; animations (`export/timing.ts`) use PowerPoint's entrance presets (Appear 1, Fly In 2, Fade 10, Wipe 22, Zoom 53) grouped and timed with SHOW's `buildSteps`, so the file plays in the order and at the times the app's show does. A diagram is its PNG (the stored preview, else drawn by the app's diagram host) carrying the Phase 6 `dcos-diagram` data and a pHYs chunk; the writer is a copy of document-studio's (the boundary forbids importing it), and `tests/integration/presentation-export.test.ts` reads it with document-studio's and diagram-studio's readers.
    - **PDF = slide SVG + svg2pdf + jsPDF.** `export/slideSvg.ts` draws a slide as plain SVG (rect, line, path, image, positioned text, linear gradients, clip paths; no foreignObject, CSS or markers): backgrounds, master and layout decorations, text laid out by `export/layoutText.ts` with the PDF fonts' own metrics (Helvetica for sans-serif slide fonts, Times for serif ones, Courier for monospaced; measured on a separate jsPDF document), shapes from `shapePath` with arrowheads as paths, pictures with crop and fit, tables cell by cell, charts from CONTENT's `layoutChart` primitives, diagrams as their PNG. One page per visible slide at the slide size (720 × 405 pt for 16:9); links are clickable; hidden slides are left out (said in the toast). "PDF with speaker notes" makes portrait 7.5 × 10 in pages: the slide above its notes, long notes continued on further pages. svg2pdf only sets a font style or text colour that differs from SVG's defaults, so every slide starts from Times, normal, black (otherwise a style used before carried over; a test fails without this). Characters outside the PDF fonts' character set (WinAnsi) are written as "?" (only those characters; the rest of the line is kept, final fix of 2026-11-15) and the texts that have them are counted in the toast, which says they "may not appear correctly"; fonts drawn as a substitute are named in the toast.
    - **Checked here:** structure tests (well-formed parts, every relationship resolves, content types, slide size, placeholders, unique ids, transitions and timing in schema order aimed at existing shapes, charts and workbooks, notes paragraphs, media signatures, theme colours, gradients, crops), PDF page count and size, text, fonts and links, e2e in Chromium and WebKit, and samples opened in Quick Look (renders text, pictures, tables, shapes and the diagram; it does not draw native charts at all, also for a plain PptxGenJS chart). Keynote and PowerPoint are not checked by this group.

16. **Round 3: integration and the verifiers' findings.** Schema 1 and the vocabulary are unchanged.
    - **Change layout matches by id first, for every placeholder** (`design/model.ts` `relayout`): the exact-id pass runs over all of the new layout's placeholders before the same-kind pass, and that before the same-family pass. Before, an earlier placeholder's looser match could take an object that a later placeholder has by id (Two content → Comparison put the left column into the heading box).
    - **A master placeholder's text style reaches every placeholder of the same family** in the master's layouts that has no master placeholder of its own id (Two content's left and right, Comparison's four, the caption, the title slide's subtitle), field by field under the "follows unless changed" rule, and from them the slides; their position and size stay their layout's. This is PowerPoint's master body text style. The master view's "Changes apply to those slides" is now true for them.
    - **Slide size:** a shape or picture on the top or bottom edge that is taller than the new slide is shrunk like any other object instead of sticking out of the slide.
    - **Tables:** deleting the row or column of the cell being edited keeps editing the nearest cell (it crashed the editor). A locked chart or diagram no longer opens its data dialog or editor on double-click or Enter. A crop side's field is limited by the opposite side (5% stays visible), so it never shows a value that was refused. Without alt text the inspector says screen readers and exported files get no description (it claimed exports mark the picture decorative, which they do not). Underline and Strikethrough (Home tab, `ui/HomeTab.tsx`) are disabled, with the reason in the tooltip, for a selected text box with no text: schema 1 has no box-level underline, so they did nothing there (final fix, 2026-11-15).
    - **Slide show and presenter window.** The show's window closing or reloading tells the presenter window the show has ended (`pagehide`); a presenter window that hears nothing from the show for 1.5 s asks (`ping`, answered by the show as an event, so a throttled show window still answers) and says the show is no longer running instead of offering buttons that move nothing only when a ping stays unanswered (5 s after the show was last heard, and at least 3.5 s after the ping). Silence alone never counts: a hidden presenter window's timers can be throttled to one tick a minute, and before the final fix (2026-11-15, `show/channel.ts`) the first tick after such a gap declared a live show lost. "Close this window" says so when the browser refuses to close it. A click on a presenter button gives the keys back to the view (Space moves the show instead of pressing Pause again). The handshake wait is 4 s, and a show whose second window cannot be used asks before showing the presenter view on its own screen (decision 13). Ctrl/⌘+S and Ctrl/⌘+P are kept from the browser during the show.
    - **Shared UI (`@dcos/ui`).** `Menu` focuses its first item once it is placed (browsers ignore `focus()` on an element that is still `visibility: hidden`, so keyboard users stayed on the button and could not export from the keyboard; Diagram Studio's menus had the same problem). Dropdowns follow their button when a toolbar scrolls and close only when it leaves the screen (a phone's ribbon scrolls as a menu opens; the menu used to close). `Dialog` is named by its title and described by its description. A `Menu` taller than the room below its button (`useAnchoredDropdown`) is capped to that room, or opens above when there is more room there, and scrolls inside itself with the focused item kept in view; a menu that fits opens as before (final fix, 2026-11-15: both Insert > Diagram menus ran off a 720 px window).
    - **Exports.** A picture background keeps its fit in the PPTX (`<a:srcRect>` crop for "Fill", `<a:fillRect>` insets for "Fit inside"; PptxGenJS stretched every one; Quick Look ignores both forms on a background, so this is checked by structure only until Keynote opens the sample), and JPEG and GIF pictures have their size read from their headers, so a JPEG background is no longer stretched in the PDF. Layouts carry only text placeholders: PptxGenJS 4.0.1 drops the type of picture and table placeholders and copies every layout placeholder onto each slide, so a picture, chart or table placed into one in the app would be covered by an empty prompt in PowerPoint and Keynote (read from the package structure; neither app has opened the files) (their prompts remain in the editor only). A table's frame is the size of its grid. `[Content_Types].xml` no longer declares parts PptxGenJS never writes (`slideMaster2`…`9`). A chart with no series or no categories is written as a labelled frame (it failed the export); a layout named DEFAULT is kept apart from PptxGenJS's own; text markers carry a random part per export, so a text that reads like one is written as text.
    - **The cross-feature case** (a themed template, another theme, a custom master, a picture, a chart, a table, a diagram, a transition, an animation and notes) is made through the UI and taken through save, reload, a saved version and its restore, the trash, a backup restored into an empty profile, the slide show and all three exports (`e2e/presentation-cross-feature.spec.ts`, Chromium and WebKit); `src/cross-feature.test.tsx` checks that design changes and every element type reach thumbnails, the PDF slide picture and the PPTX, and that the PPTX click groups are the show's build steps.
