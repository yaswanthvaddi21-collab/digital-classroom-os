# 0012 — Diagram format in Phase 5: schema 3 from a frozen schema-2 vocabulary; groups, layers and waypoints

**Status:** Accepted in Phase 5 (Round 1). Extended in Round 2 (the G-DRAWIO fields in decision 2 and decision 8) and Round 3 (the Round 3 rules at the end).

## Context

Phase 5 adds groups, locks, layers, hidden shapes, rotation, links, tooltips, custom properties, manual waypoints, movable connector labels, extra connection points and many new shape kinds to Diagram Studio. Each one changes what a stored diagram can contain.

Saved diagrams were schema 2 (`serializeDiagram` always wrote 2; v0.1.0 wrote 1 and opens anything above 1 read-only; the Phase 4 build, git `206e080`, opens anything above 2 read-only). The owner's rules apply: saved diagrams keep their ids and content, stored content is never rewritten on open, there are no destructive migrations, and older builds must keep editing what they can. Documents embed diagrams as diagram content (`diagramEmbed` source), so the same rules hold there. [ADR 0011](0011-document-format-phase4.md) solved the same problem for documents with a frozen vocabulary; this record mirrors it.

## Decision

1. **Schema 3 is decided by a frozen schema-2 vocabulary.** `packages/diagram-studio/src/compat.ts` holds `SCHEMA2_VOCABULARY`: the content, node and edge top-level fields, the 16 shape kinds, the shape-data and connector-data fields, the arrow modes, the 11 markers, the 4 line types, the handle ids `t r b l` (and `null`), the settings fields and values, and the viewport fields of the Phase 4 build. It also lists `width` and `height` inside shape data, which the Phase 4 diagrams.net importer copied there (the importer no longer does). It is never edited. `schemaFor(content)` returns 3 when stored content uses anything outside it (a field outside the lists with a value, a kind, line type, handle, marker, arrow mode or setting value outside them) and 2 otherwise. `serializeDiagram` sets `schemaVersion` from it on every save, so the number follows the content: a diagram that uses only schema-2 features is saved as 2 and the Phase 4 build still edits it, and removing the last schema-3 feature makes it schema 2 again. Templates, the empty diagram, diagrams.net imports and `.dcosdiagram` imports go through the same rule. `DIAGRAM_SCHEMA` (the newest schema this build reads) is 3. A later feature makes diagrams schema 3 without touching `compat.ts`.

2. **The new fields are optional, absent by default, and checked on load.** A field at its default is not stored, so a diagram that does not use a feature stores exactly what it stored before. `deserializeDiagram` reads each field through a reader in `model.ts`; an invalid value is left out (never a crash), and the stored input is never changed.

   | Field | Where | Meaning | Valid values |
   |---|---|---|---|
   | `parentId` | node | The group or container the shape is in; `position` is then relative to it | an existing node, not itself, no loops |
   | `locked` | node | Cannot be moved, resized, edited or deleted | `true` (stored only when true) |
   | `hidden` | node | Not shown or exported (diagrams.net hidden cells) | `true` (stored only when true) |
   | `layer` | node | Layer id; absent = the first layer | an id in `layers` |
   | `layers` | diagram | Layers bottom first: `{ id, name, visible, locked }` | unique non-empty ids; absent when there are none |
   | `rotation` | shape data | Degrees clockwise about the centre | finite; normalised to (−360, 360); 0 is not stored |
   | `link` | shape data | Address the shape opens | http, https, mailto, relative or `#anchor`, diagrams.net `data:page/id,…` only |
   | `tooltip` | shape data | Text shown on pointing | non-empty string |
   | `properties` | shape data | Custom properties (diagrams.net "Edit Data") | string → string, up to 200 |
   | `waypoints` | connector data | Bend points, source to target, in flow coordinates | finite points, up to 500 |
   | `labelPosition` | connector data | Label position along the connector, 0 (source) to 1 (target) | [0, 1]; 0.5 is not stored |
   | `sourcePort`, `targetPort` | connector data | Attachment beyond the side handles | `'perimeter'`, or `{x, y}` fractions of the shape's box in [0, 1] |
   | kind `group` | shape data `shape` | An invisible container shape for a group | — |
   | `opacity` | shape data | Opacity of fill and outline in percent (G-DRAWIO; text stays opaque, as in diagrams.net) | [0, 100); 100 is not stored |
   | `fontFamily` | shape data | Font family of the text (G-DRAWIO; the device's fallback when not installed) | letters, digits, spaces, `, . ' " _ -`; up to 120 characters |
   | `textAlign`, `verticalAlign` | shape data | Where the text sits (G-DRAWIO) | `'left'`/`'right'`, `'top'`/`'bottom'`; centre and middle are not stored |
   | kind `image`, `image` | shape data | A picture (G-DRAWIO, from diagrams.net image cells) | embedded data: URL of PNG, JPEG, GIF, WebP, BMP or SVG, up to 8,000,000 characters |

   Structural fields (`parentId`, `hidden`, `locked`, `layer`) sit on the node, like React Flow's own `parentId` and `hidden`. What a shape or connector looks like and carries sits in `data`, which React Flow hands to the renderers. React Flow properties that depend on these fields (`draggable`, `deletable` and `selectable` for locks and locked layers, `hidden` for hidden layers) are derived when rendering and never written back into the stored fields. A shape made from another one (quick connect, Tab child) takes its look and its group and layer, but not its text, link, tooltip or properties.

3. **Groups are React Flow parent nodes.** A group is a node (kind `group`, drawn invisible, its area selectable) and the shapes in it have `parentId` set to it, with positions relative to it, which is React Flow's own model: moving the group moves its contents, and nested groups are parents of parents. Any node may be a parent, so swimlane containers (BPMN pools and lanes) use the same field. `extent: 'parent'` is not stored; whether children may leave their container is a runtime choice per container kind (a stored `extent` would make the diagram schema 3 like any unknown field). React Flow needs parents before children in the node array: `parentsFirst()` reorders on load only when the stored order breaks that, and invalid parent links (missing, self, loops) are dropped. Copy and paste remap `parentId` to the copied group; a child copied without its group is pasted at its canvas position, outside any group. Edits that place or compare shapes across groups work on canvas positions and store the result in each shape's own frame (`canvasPosition`, `toFrame` and `inCanvasFrame` in `model.ts`): a quick-connect drop point, the shape an arrow click or Enter adds next to a shape in a group (which joins that group), alignment and auto-layout. Select all (Ctrl+A) leaves hidden shapes out, so Delete and Duplicate never reach shapes the user cannot see. The diagrams.net exporter writes real groups: a group cell with its shapes inside it at their stored (relative) positions, which is also how diagrams.net stores them (decision 8).

4. **Layers are a diagram-level list; shapes point at them.** The first layer is the default: shapes without `layer` are on it, so a diagram without layers needs no field at all. A layer's `visible` and `locked` apply at render time, so hiding a layer never rewrites its shapes. Layers are part of each undo step.

5. **Waypoints are absolute flow coordinates.** As in diagrams.net, bend points stay where they are when the end shapes move; pasting moves them with the copy. `sourceHandle` and `targetHandle` stay as they are next to a port, so the side a connector leaves from is still known when a port cannot be honoured.

6. **Content from a newer version stays protected.** Content with `schemaVersion` above 3 opens read-only and `getContent()` hands back the exact object it was given. Unknown fields inside shape or connector `data` are kept on load and make the diagram schema 3 when saved; unknown top-level node and edge fields are dropped, as before.

7. **The app's own file format is the stored content in an envelope.** A `.dcosdiagram` file is `{ format: "dcos-diagram", version: 1, app, title, diagram }`, where `diagram` is the stored `DiagramContent` with its own schema number. Opening one is strict: wrong format, a newer envelope or schema, an unknown shape kind or line type, an unknown node, edge, content, settings or saved-view field, a connection point other than the four side handles, more bend points or properties than a diagram keeps (or a property with no name), duplicate ids, dangling connectors, damaged values and unsafe links are refused with a sentence that says why; nothing is created. A valid file always becomes a new diagram (never merged), stored in the form this version saves. The editor exports it from the Export menu; the Diagrams list imports it ("Import diagram file"), and the editor's "Open file…" opens it or a diagrams.net file as a new diagram.

8. **diagrams.net files map the model to diagrams.net's own forms (G-DRAWIO).** `drawio.ts` walks the cell tree; `drawioFeatures.ts` holds the per-field mappings. Export and import, both ways:

   | Model | diagrams.net |
   | --- | --- |
   | group (`parentId`) | a `group` cell (or `container=1` for any other parent) with its shapes as child cells, at the same relative positions |
   | `layers` | layer cells under the root (`visible="0"` hidden, `style="locked=1;"` locked), shapes under their layer; with no `layers`, the single default layer `1` |
   | `hidden` / `locked` | `visible="0"` / `locked=1` |
   | `rotation`, `opacity`, `fontFamily`, `textAlign`, `verticalAlign` | `rotation=`, `opacity=` (0–100), `fontFamily=`, `align=`, `verticalAlign=` |
   | `link`, `tooltip`, `properties` | a `<UserObject>` wrapper with `link`, `tooltip` and one attribute per property (diagrams.net's Edit Data) |
   | `image` kind, `data.image` | `shape=image;image=data:image/png,<base64>` (diagrams.net drops `;base64`, which would end the style entry) |
   | `waypoints` | `<Array as="points">` in the edge geometry; canvas coordinates, offset by the edge's parent when a file puts the edge inside a container |
   | `labelPosition` (0..1) | the edge geometry's `x` (-1..1) |
   | `sourcePort` / `targetPort` | a fixed point as `exitX/exitY` (`entryX/entryY`); `perimeter` as a floating end (no point); `dcosSourcePort`/`dcosSourceHandle` keys make our own files exact |

   A file drawn in diagrams.net is mapped from these keys; a side-centre exit point is a plain handle (so simple files stay schema 2), any other point is a port. Swimlanes holding shapes become the BPMN `bpmnPool` / `bpmnLane` kinds through the hook `DRAWIO_SWIMLANE_KINDS` (a transparent outline container when those kinds are not registered). Every approximation adds one counted note (`IMPORT_NOTES`): hidden shapes and hidden layers are imported hidden and named (DS-R2); gradients, shadows, sketch and glass styles, separate fill/outline/text transparency, italic/underline, formatting inside a label, pictures inside text, icons, text outside the shape (moved inside, against that side), vertical text, web pictures (an empty frame: the app never downloads), unsafe links, page links to pages not imported, edge links/properties, locked, hidden or transparent connectors, connectors on hidden layers, label offsets, several labels on one connector, connection-point offsets, connectors ending on connectors, loose connectors (with the right reason and plural, DS-R7), collapsed containers (opened at their full size) and the pages not imported. `fromDrawio(text, { page })` imports any page; `drawioPages(text)` lists them. Pictures are kept only as embedded data: URLs of PNG, JPEG, GIF, WebP, BMP or SVG up to 8 MB of text (`readImage`), drawn through `<image>`, where browsers run no scripts.

## Consequences

- A diagram that uses no Phase 5 feature stays schema 2, so the Phase 4 build keeps editing it, and v0.1.0 keeps refusing it exactly as before. A diagram that uses one opens read-only in the Phase 4 build, with its "Download original data" escape hatch.
- **Backups accept schema-3 diagrams.** `packages/local-storage/src/backup.ts` now checks each item and version against the newest schema of its own kind (`MAX_CONTENT_SCHEMA_BY_KIND`: documents 2, diagrams 3), and a backup's `schemaVersion` may be up to 3, so this build restores its own backups of schema-3 diagrams. See [ADR 0007](0007-backup-format.md). A backup's `schemaVersion` is the highest schema in the file. A backup that holds one schema-3 diagram, or one saved version of one, is therefore schema 3, and the Phase 4 build refuses the whole file, documents included, with "this backup contains content from a newer version of the app". A backup stays schema 2, and still restores there, only while no diagram and no saved version in it uses a Phase 5 feature. Removing the feature from a diagram later does not change the versions already saved.
- Round 2 adds the editing (G-CANVAS, G-CONNECT), the diagrams.net mapping (G-DRAWIO, decision 8) and the vector export (G-EXPORT). A diagrams.net export is never silent: `drawioExportNotes` (the `DRAWIO_EXPORT_LOSSES` table in `drawioRegistry.ts`) names what a `.drawio` file cannot hold, with counts, in the export toast of the editor and of a diagram embedded in a document. Since G-DRAWIO only two entries remain: custom properties whose names diagrams.net cannot store, and a shape on another layer than its group.
- Embedded diagrams in documents are diagram content and follow the same rules; a document holding a schema-3 diagram keeps it unchanged.
- The Network and Timeline templates now use library shapes, so a diagram started from them (or from the BPMN and UML sequence, activity, state and use case templates) is schema 3 and opens read-only in the Phase 4 build. Diagrams already saved from the old templates stay schema 2.

## Round 3 rules (integration)

- **Layers of shapes in groups.** A shape that names no layer is on the layer of the nearest group or container it is in that names one, else on the bottom layer (`layerIdOf`). A layer change pins every shape to its layer as the layers were before the change, so reordering never moves a shape. A pasted shape whose layer no longer exists goes to the current layer (or names none when the diagram has no layers), so a dangling id never keeps a diagram at schema 3.
- **Locked groups.** A group is one object: the shapes inside a locked group are fixed with it, and the group is not ungrouped, refitted or removed with its shapes. Containers (pools, lanes, boundaries) do not lock what they hold; a shape nudged inside a locked container stays in it.
- **Connector labels.** A connector without a label stores no `labelPosition`.
- **Exports** take visibility and stacking from the canvas's own rules (`renderNodes`), so the SVG, PNG and PDF draw what the canvas draws.
